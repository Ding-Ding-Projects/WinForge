# Safe WinUI automation capture · 安全 WinUI 自動截圖

## Contract · 合約

DEBUG builds may opt in with an absolute `.png` path of at most 1,024 characters on a fixed or removable local drive through `WINFORGE_CAPTURE_PATH`; UNC, mapped-network, relative, and non-PNG paths fail closed. `WINFORGE_CAPTURE_DELAY_MS` is bounded to 1–30 seconds; optional width/height values are bounded to 640–3840 and 480–2160. After the shell loads, WinForge renders its real root visual through `RenderTargetBitmap`, composites premultiplied pixels against the root's actual light/dark theme, writes a unique same-directory partial PNG, flushes it, and atomically promotes it. Success logs only dimensions; failure logs contain only exception type and HRESULT, never the requested path. Release builds and launches without the path do nothing. · DEBUG build 只會接受 `WINFORGE_CAPTURE_PATH` 明確指定、最多 1,024 字元、位於本機 fixed／removable drive 嘅絕對 `.png` 路徑；UNC、mapped network、相對或者非 PNG 路徑全部 fail closed。Delay 限 1–30 秒，可選闊／高限 640–3840 同 480–2160。Shell 載入後，WinForge 用 `RenderTargetBitmap` 輸出真實 root visual，按 root 實際 light／dark theme 合成 premultiplied pixels，先 flush 同目錄唯一 partial PNG，再原子升格。成功只記尺寸；失敗只記 exception type 同 HRESULT，唔會記要求路徑。Release build 或冇 path 嘅 launch 完全唔做嘢。

## Safety and failure modes · 安全同故障模式

The repository driver applies the same local-path rules, removes an older destination once a new attempt begins, creates unique request/final paths, and restores its capture environment immediately after launch. It validates dimensions and color diversity, then every live-tree and `PrintWindow` path reaches the requested filename only through a same-directory `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)` promotion. It retries both temporary-file cleanups and stops the original process through its retained handle rather than resolving a reusable PID. It never uses `CopyFromScreen`; this prevents an overlapping app from leaking into WinForge evidence. Blank frames are rejected, and process or temporary cleanup failure is reported rather than silently claiming success. Capture exceptions can never crash the app. · Repo driver 套用相同本機路徑規則，新擷取開始就移除舊 destination，再建立唯一 request／final path，launch 後即時還原 capture environment。佢驗證尺寸同色彩多樣性；所有 live-tree 同 `PrintWindow` 路徑都只會經同目錄 `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)` 原子升格到要求檔名。兩種 temp file 都會重試清理，並經保留嘅原始 process handle 停止自家 app，唔會追一個可重用 PID。佢永遠唔用 `CopyFromScreen`，避免遮住 WinForge 嘅其他 app 漏入證據；空白畫面會被拒絕，process 或 temp 清理失敗亦會如實報告，唔會靜雞雞當成功。Capture 例外亦唔可以拖冧 app。

## Verification · 驗證

The PowerShell 5.1 parser passes, the capture-policy/source-contract harness passes **9/9**, and the atomic driver completed a process-owned `mixer` capture through the live-tree path with no surviving `.winui-*` or `.driver-*` temporary file. A bounded runtime scan found zero requested-target matches in WinForge's persistent crash, startup, and owned logs. Separate fresh-handle LowLevel runs produced and inspected app-owned **1264×791**, **784×691**, and canonical **1284×811** frames plus independent **1280×800**, **800×700**, and **1300×820** window captures. All retained evidence is dark-theme accurate and opaque; no clipping, overlap, foreign-window pixels, or desktop/process leakage was observed. · PowerShell 5.1 parser 通過，capture-policy／source-contract harness **9/9** 全過；atomic driver 經 live-tree 路徑完成自家 `mixer` 擷取，冇遺留 `.winui-*` 或 `.driver-*` temp file。有限 runtime scan 喺 WinForge persistent crash、startup 同自家 logs 搵到零個要求 target match。另一組 fresh-handle LowLevel run 產生並檢視 app-owned **1264×791**、**784×691**、正式 **1284×811** 圖，同獨立 **1280×800**、**800×700**、**1300×820** window capture。所有保留證據都符合 dark theme 而且不透明，冇裁切、重疊、其他視窗 pixels，亦冇 desktop／process 洩漏。
